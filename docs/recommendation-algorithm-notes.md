# 推荐算法已知机制说明(共线与安全偏好)

> 本文档对应审计报告 `recommendation-algorithm-audit.md` 的 P1-5 项:共线消融需要真实候选分布与线上指标,在数据可用之前,这里明确记录已知的三条共线路径和系统性行为,作为有意为之的安全策略留档。**权重暂不调整**(审计第 8 节:数据可用前不建议单权重调参发布)。

## 版本

- `recommendation-v0.3` / `risk-v0.3`(2026-08,修复见文末变更记录)

## rating 的双重计分

`rating` 同时进入两条路径:

1. `ratingFactor = rating / 5`,外层权重 25;
2. `ratingRisk`(0/20/60/100),风险内部权重 0.25,再经外层 risk 权重 20 与 confidence 折算。

以 3.9 分 vs 5.0 分为例,总影响 ≈ `25×(1−0.78) + 20×0.25×conf×(100−0)/100` = 5.5 + 5×conf 分。rating 的**有效敏感度高于表面配置的 25 分**。

## 数据质量的重复惩罚

价格、营业信息、评价数量缺失会同时:

1. 降低 `DataCompleteness`(外层权重 10);
2. 增加 `dataInsufficientRisk`(风险内部权重 0.25);
3. 降低 confidence,进而放大 `uncertaintyRisk=50` 的中性化。

数据质量至少通过三条路径影响排序,合计有效影响远超配置表任何单项。

## 系统性结果:成熟门店偏好

上述共线使算法天然偏好数据充足、历史口碑稳定的成熟连锁门店,压制新店/小店。这是**有意保留的安全策略**("低后悔"目标的保守面),不是缺陷;但其强度未被量化。

## 后续消融计划(需要数据)

1. 建立离线回放集(利用 v0.3 落库的 `random_seed` 与随机前 `selection_snapshot_json`)。
2. 分别置零 `ratingRisk` 内部权重 / `completeness` 外层权重,对比候选池构成变化与踩坑率。
3. 若重复惩罚的边际收益不显著,合并为单一"数据质量"因子并重标定权重。
