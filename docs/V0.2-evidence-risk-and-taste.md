# LowRegret V0.2：数据去水与用户偏好闭环

## 版本与兼容性

- 产品与契约版本：`0.2.0`
- 风险算法：`risk-v0.2`
- 推荐算法：`recommendation-v0.2`
- 保留 V0.12 的默认正餐、四类可选纠偏、候选多样化、6 家候选池及 5 次 reroll。
- 三个 POST 接口与请求体保持兼容；`RecommendationResponse.risk` 新增必填 `confidence`。

## 当前数据流

```text
POI
→ 距离/预算/品类/营业状态硬过滤
→ EvidenceProvider（File 默认，Empty fallback，逐餐厅降级）
→ RiskEngine：五项风险 + confidence
→ HIGH 风险剔除
→ LowRegretScore：质量/距离/预算/品类/风险可信度/TasteProfile
→ Top-10 品类多样化
→ 加权有限随机
→ 冻结最多 6 家候选
→ 推荐 1 家 / 最多 5 次不重复 reroll
→ LIKE/NORMAL/DISLIKE 更新画像，仅影响下一次新推荐
```

## Evidence

`FileEvidenceProvider` 将文件 DTO 转为统一 `RestaurantEvidence`。统一评论字段包括外部 ID、正文、1～5 分评分和时间；Evidence 还包含来源、状态与抓取时间。默认文件为 `classpath:evidence/restaurant-evidence.json`，可由 `EVIDENCE_FILE` 覆盖，每家最多 200 条评论。

缺文件、损坏文件、无匹配餐厅、Provider 抛异常均转换为 `UNAVAILABLE` 或 `NO_DATA`，RiskEngine 提高数据不足风险并降低 confidence，主推荐不失败。

后续真实平台只需实现 `EvidenceProvider` 并完成 DTO 映射，不允许让平台 DTO 进入 RiskEngine。

## risk-v0.2

五项因子固定为 `ratingRisk`、`templateRisk`、`burstRisk`、`trendRisk`、`dataInsufficientRisk`，单项和总分范围均为 0～100。默认总分权重为 25% / 20% / 15% / 15% / 25%，等级边界为 20 / 40 / 60。

- 模板评论：清洗后的中文字符 3-gram Jaccard，相似度 0.82；并查集合并相似簇，不足 10 条不判断。
- burst：3 日窗口，至少 20 条、峰值至少 12 条；峰值/窗口外历史基线从 3 倍起计风险，8 倍满风险。
- 趋势：最近 30 日对比此前 90 日，样本至少 5 / 10 条；均分变化 0.4 或低分率变化 0.2 判定 UP/DOWN，否则 STABLE，样本不足 UNKNOWN。
- confidence：25% POI 完整度 + 75% Evidence 数量及文本/评分/时间覆盖率，Evidence 目标样本 30 条。
- 低 confidence 排序时使用不确定性风险补偿，避免缺数据候选获得虚假低风险优势。

阈值、权重、样本下限、等级和版本集中在 `backend/src/main/resources/application.yml` 的 `elma.risk.*`；推荐补偿在 `elma.recommendation.*`。

## TasteProfile

`user_preference.preference_json` 保存 `schemaVersion=2` 的追加式画像快照。旧版请求条件 JSON 自动忽略；若没有 V2 快照但存在历史反馈，则按反馈时间、餐厅与候选距离重建。

画像维度为细品类、价格档和距离档：价格档 `≤30 / 31～60 / 61～100 / >100`，距离档 `≤500 / 501～1000 / 1001～2000 / >2000`。每次反馈先将已有权重乘 0.95，再应用 LIKE +1、NORMAL +0.1、DISLIKE -1，单项限制在 [-3, 3]。

排序偏好由品类 50%、价格 25%、距离 25% 合成 [-1, 1]，最多调整 LowRegretScore ±15 分。无画像的新用户调整为 0。画像在反馈事务内更新，当前推荐会话候选池不重排。

## Persistence

Flyway `V2__risk_v02_and_recommendation_log.sql`：

- `risk_result` 增加 `confidence`、`factors_json`。
- `recommendation_candidate` 增加 `risk_confidence`、`risk_factors_json`，reroll 从快照完整恢复风险视图。
- `recommendation_log` 增加 `recommended_restaurant_id` 并从 `current_restaurant_id` 回填；reroll 仅修改当前展示餐厅，不覆盖首次推荐餐厅及首次分数。

## 预留与暂缓

- 模板、burst、趋势分析均有独立接口，可替换实现。
- 未接真实评论平台；主资源为空，测试夹具验证 Evidence 确实改变风险。
- 高德品类粒度暂不能可靠细分到湘菜等菜系。
- 远程 Evidence 后续需要批量接口、缓存、超时和隔离。
- 追加式画像暂不解决多实例并发竞争；反馈接口暂无数据库级幂等约束。
